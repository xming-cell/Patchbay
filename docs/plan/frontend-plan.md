# 第一章 IA（信息架构）

## 1.1 页面清单与路由

| 路由 | 页面 | 让人完成的动作（不是「显示什么」） | 功能 |
|---|---|---|---|
| `/` | 总览 | 30 秒判断「这台机器现在能不能开工」，缺什么点哪里 | F-01、F-08 |
| `/providers` | 模型接入 | 添加/测试/选择一个 Anthropic 兼容 provider，确认 Doctor 绿灯 | F-02、F-03 |
| `/chat` | 对话 | 选 provider 和目录，说一句话，看它边跑边回 | F-04 |
| `/history` | 历史 | 找回本软件里跑过的会话，只读回看 | F-05 |
| `/env` | 环境变量 | 只读看清 User/Machine 变量和 PATH；要改就跳系统对话框 | F-06、F-07 |
| `/styleguide` | 设计自检 | 确认 tokens 与组件全状态；只在开发时看 | F-08 |
| `/system` | 系统面板（v1.1） | 看进程/端口/全局包；v1 不实现，只留路由占位 | F-11、F-12 |

v1 只有前六个路由可达；`/system` 在导航里显示为「即将支持」或直接隐藏，二选一，不半开。

## 1.2 导航

```text
┌──────────────────────────────────────────────────────────────┐
│  CC Hub   总览   模型   对话   环境   历史          [设置]  │
└───────┬──────────────────────────────────────────────────────┘
        │
        ├─ 总览 (/)
        │    ├─ 工具链详情（抽屉）
        │    └─ Provider 状态 → /providers
        ├─ 模型 (/providers)
        │    └─ Provider 详情 / Doctor 检查（右侧抽屉）
        ├─ 对话 (/chat)
        │    └─ 会话历史 (/history)
        ├─ 环境 (/env)
        │    └─ 系统环境变量对话框（外部窗口）
        └─ 历史 (/history)
```

决策：**没有独立的「设置」一级页**。Provider 就是设置；主题/默认目录放总览右上角的齿轮抽屉。
理由：这个 app 的「设置」主要就是模型接入，单独开一页会让主链路多一次跳转。

## 1.3 每页的信息层级

**总览（/）** —— 从上到下三块：
1. 工具链卡：Node / npm / Claude Code 三个状态点 + 版本 + 路径；缺失时给「安装」按钮。
2. Provider 卡：当前默认 provider + Doctor 状态；未测试/失败时给「去测试」。
3. 下一步：一句人话，例如「Provider 未测试，先测一下」或「可以开始对话」。
底部放 v1.1 模块占位（进程 / 端口 / 全局包 / 命令面板），灰掉，不抢主链路。

**模型接入（/providers）** —— 左列表右详情：
- 左：provider 名称 / 模型 / 最近一次 Doctor 状态；顶部「+ 添加」。
- 右：`base_url`、`model`、`auth_style`、`key_ref`（只显示引用，不显示明文）、厂商文档链接。
- 主按钮「测试连接」；测试结果按四项列出：对话 / 流式 / tool use / 长上下文。
- 失败时保留「仍然保存」，但 chat 页会禁用并显示原因；不允许假装绿灯。

**环境变量（/env）** —— 顶部一条只读横幅，下面是：
- Scope tabs：用户变量 / 系统变量；搜索框；「打开 Windows 环境变量」按钮；「修改教程」链接。
- 表格：名称 / 值（密钥打码）/ 来源 / 操作（复制、查看详情）。
- PATH 单独一块：拆成 chips，标出「存在 / 不存在 / 重复」；指向 Node/npm/Claude 的条目用强调色。
- 详情抽屉：完整值（默认打码）、`REG_SZ` / `REG_EXPAND_SZ`、scope、复制、导出单条。
- 没有任何删除/编辑按钮；删除只出现在教程里。

**对话（/chat）** —— 左侧会话列表（可收起）、中间消息流、顶部上下文条、底部输入框。
上下文条永远显示：`Claude Code · provider · model · cwd`；这是这个页面最容易搞错的事。
消息流里 tool call 折叠成单行，可展开；流式时「发送」变「停止」。

**历史（/history）** —— 左列表右只读回放；回放区顶部横幅「这是回放，不能继续输入」。

## 1.4 状态矩阵

总览的工具链四态：

| 状态 | 判定 | 总览表现 | 下一步 |
|---|---|---|---|
| Node 缺失 | `where node` 失败 | 红点「未安装 Node」 | 打开安装向导 |
| Node 过旧 | 低于 Claude Code 要求 | 黄点「版本过低」 | 升级 Node（不静默） |
| Claude 缺失 | `where claude` 失败 | 红点「未安装 Claude Code」 | 打开安装向导 |
| 正常 | Node + Claude 都可用 | 绿点 + 版本 | 去模型接入 |

Provider 五态：

| 状态 | 表现 | 能否进 chat |
|---|---|---|
| 未配置 | 灰点「还没有 Provider」 | 否 |
| 未测试 | 黄点「未测试」 | 否 |
| 测试中 | 蓝点 + 进度 | 否 |
| 通过 | 绿点 + 四项全过 | 是 |
| 失败 | 红点 + 第一项失败原因 | 否（可保存） |

对话六态：

| 对话状态 | 表现 | 能否输入 |
|---|---|---|
| 无 provider / 无目录 | 空状态，两个选择器高亮 | 否 |
| 空闲 | 输入框可用 | 是 |
| 流式输出中 | 最后一条带光标，「发送」变「停止」 | 否（只能停止） |
| 进程已退出 | 灰字「进程已退出（code 0）」 | 是 |
| 进程异常退出 | 红字 + 最后 3 行 stderr | 是 |
| 工具不可用 | 输入框禁用 + 去 Doctor 的链接 | 否 |

环境变量三态：

| 状态 | 表现 |
|---|---|
| 加载中 | 表格骨架，不显示半张表 |
| 空 | 「没有读到环境变量」+ 重试 |
| 错误 | 红条 + 错误首行 + 重试；不显示可能过期的缓存 |

## 1.5 空状态与错误状态清单（写组件前必须都有答案）

| 位置 | 空状态文案 | 错误状态 |
|---|---|---|
| 总览 | 「还没有检测环境」+ 重新检测 | 检测失败：整页降级成一条红条，不显示半张卡 |
| 模型接入 | 「还没有 Provider」+ 添加 | 保存失败：抽屉不关，字段下标红 |
| 对话 | 「选一个 Provider 和目录开始」 | 见 1.4；stderr 最多显示 3 行 |
| 环境变量 | 「没有匹配的变量」 | 读取失败红条；不显示删除/编辑 |
| 历史 | 「还没有会话」 | 「这个会话读不到」+ 文件路径，不崩 |

# 第三章 tokens

落地文件：`frontend/src/styles/tokens.css`。组件里只允许引用变量，不允许裸数值。

## 3.1 间距刻度（只允许这七档）

```css
--sp-1: 4px;  --sp-2: 8px;  --sp-3: 12px; --sp-4: 16px;
--sp-5: 24px; --sp-6: 32px; --sp-7: 48px;
```

## 3.2 字号阶梯（只允许这五档）

| 变量 | 值 | 行高 | 用途 |
|---|---|---|---|
| `--fs-xs` | 12px | 1.5 | 路径、时间戳、次要说明 |
| `--fs-sm` | 13px | 1.5 | 表格、列表行 |
| `--fs-md` | 14px | 1.6 | 正文（默认） |
| `--fs-lg` | 16px | 1.4 | 页面标题 |
| `--fs-xl` | 20px | 1.3 | 空状态的标题 |

字体栈：`system-ui, "Segoe UI", "Microsoft YaHei", sans-serif`；代码/路径用
`ui-monospace, "Cascadia Code", Consolas, monospace`。

## 3.3 颜色（只用语义名，不写十六进制）

```css
--bg:         #1b1b1f;   /* 页面底 */
--surface:    #232327;   /* 卡片、列表行 */
--surface-2:  #2b2b31;   /* 输入框、抽屉 */
--border:     #35353c;   /* 1px 分隔 */
--border-strong: #4a4a54;/* 输入框聚焦前 */
--text:       #e6e6e9;
--text-dim:   #9a9aa3;   /* 次要信息 */
--accent:     #4c8dff;   /* 唯一强调色：主按钮、选中、聚焦环 */
--accent-fg:  #ffffff;   /* 强调色上的文字 */
--ok:         #3fb950;   /* 通过、正常 */
--warn:       #d29922;   /* 未测试、版本过低 */
--danger:     #f85149;   /* 失败、错误条 */
```

深色为默认；跟随系统主题在收口卡再补。Doctor 的「测试中」用 `--accent`，不新增蓝色。

## 3.4 圆角与边框

```css
--r-sm: 4px;  --r-md: 6px;  --r-lg: 10px;
--bw: 1px;
--focus-ring: 0 0 0 2px var(--accent);
```

阴影只用一处：抽屉与对话框 `--shadow-overlay: 0 8px 32px rgb(0 0 0 / 45%)`。其余一律不加阴影。

## 3.5 四条硬规则（004 卡写进 `guards.py` 或 lint）

1. `.vue` / `.css` 里出现 `px` 字面量，必须是 0 或在 `tokens.css` 内。
2. 出现 `#` 开头的十六进制颜色，只允许在 `tokens.css` 内。
3. 组件不直接调 `fetch`，只走 `src/api/`（已有规则，此处重申）。
4. **环境变量页不出现删除/编辑按钮**；Provider key 默认打码，日志里不允许出现明文。

## 3.6 组件只做三个（v1）

`Button`（primary / ghost / danger 三态）、`Field`（label + input + 错误行）、`Dialog`（遮罩 + 抽屉/居中两种）。
状态点用 `span.status-dot` + 语义色 class，不单独做组件；表格、tabs 用原生元素 + tokens。
第四个组件出现时先讨论，不直接加。
