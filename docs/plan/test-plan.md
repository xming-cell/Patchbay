# 总计划

> 状态：草案（2026-11-24）。本文件是本轮重做的总计划，具体任务卡在 `specs/`。
> 可随时调整；调整这里不需要改 `specs/CURRENT`。
>
> 上一版（CC-Roster，项目3）的教训：25 张卡、app 内自建「主数据」、前端靠 Penpot 导 PNG，
> 导致复杂度失控、设计稿与代码脱节。这一版针对性地砍掉这三件事。

## 1. 一句话产品

打开面板，看到本机每个 AI 编程工具**当前用的是哪个供应商 / 模型**；没配置的工具可以一键生成
最小配置；要换时选一个预设、看 diff、确认写入，失败可回滚。

## 2. 本轮三条策略

| 策略 | 含义 | 由此砍掉的东西 |
|---|---|---|
| 配置优先读本地 | 工具自己的配置文件是唯一真相源；app 只读，只在用户确认后增量写 | app 内的 provider 主数据、绑定矩阵、快照、防漂移、冲突重检 |
| 一工具一模型 | 每个工具同一时刻只有一个生效的 provider + model | 多供应商绑定、切换矩阵 |
| 配置简洁 | app 自身只有一个人类可读的 YAML（预设 + 设置） | 数据库、迁移、索引重建 |

## 3. 范围

**做**

- 发现本机 4 个工具（Claude Code / Codex CLI / DSH），解析当前配置
- 如果没有读取到本地配置，可以手动进行配置工具
- 一个最小可用的 Web UI

**不做（v1）**

- app 内数据库
- 多工具同时切换 / 批量操作
- 明文密钥入库
- e2e 自动化（手动验收 + 截图存档即可）

## 4. 数据模型草案（后续根据实际情况更改）

    Tool    : id, name, config_path, status(readable | missing | parse_error | unconfigured),
              current: { provider, model, base_url, key_ref }
    Preset  : id, name, provider, base_url, model, key_ref
    Settings: theme, last_tool

app 只把 Preset + Settings 存进一个 `config.yaml`；Tool 每次从磁盘现读，不落库。

## 5. 「读不到」的三种情况

| 情况 | 判定 | 行为 |
|---|---|---|
| 文件不存在 | 路径不存在 | 允许「生成最小配置」，但必须预览，不静默写 |
| 解析失败 | 存在但 JSON / TOML 非法 | 只显示错误，禁止写入 |
| 有文件但缺 model 字段 | 解析成功、字段缺失 | 显示「未配置」，写入前必须 diff |

## 6. 前端策略：代码即设计稿

- 不做独立设计工具，不导出 PNG 快照。
- `src/styles/tokens.css` 定义颜色 / 间距 / 圆角 / 字号；`/styleguide` 路由就是活的设计规范。
- 每张前端卡的验收 = 打开浏览器点，Playwright 截图存 `docs/design/shots/`。
- 不引组件库，只自建 3 个基础组件（Button / Field / Dialog）。
- 桌面 1280 优先，窄屏在收口卡补。

## 8. 每张卡的节奏（防走偏机制）

1. **开工前**：我把 `specs/NNN/tasks.md` 的 scope + DoD 写成 5 行摘要发给你，你点头才开工。
2. **做完**：贴 `uv run python scripts/check.py` 完整输出 + 「这张卡你应该能解释的 3 个问题」。
3. **你过了才提交**：一张卡一个 commit，`specs/CURRENT` 同步更新。
4. 卡内 30 分钟搞不定就停，按 `AGENTS.md` 第 6 条写 `PROGRESS.md`「未决问题」。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 四家配置格式差异大，parser 互相污染 | 004 的注册表隔离，每家一个 parser，失败只影响自己 |
| 写配置是危险操作 | 008 强制「先备份、再 diff、再原子写」；解析失败一律拒写 |
| 前端返工 | tokens 先定；一张卡只做一个页面；验收必须打开浏览器 |
| 计划再次膨胀 | 新需求先进本文件第 9 节，不直接开卡 |
